# Routina Fit

每天同一份清單，點一下算一下。Routina 家族的成員之一，獨立安裝，manifest 只有一行 `VIBRATE`。

規則只有一條：**紀錄是執行的副產物，訓練中不打字。** 首頁點一下就是一下，一天結束按一下結算，
全程沒有輸入任何數字。

## 畫面

**首頁就是今天要做的清單**，整列是一顆按鈕：點一下加一下、長按連續加、往左滑露出編輯與刪除，
最下面一列 ＋ 加新的一項。清單每天換日時會照「設定 → 每天的預設清單」重新長出來。

底部三個分頁：**今天**、**動作**（動作庫）、**紀錄**（依日期分段的歷史）。
編輯、加一項這些是任務不是地方，一律全螢幕蓋上去、不顯示分頁列。

## 拿掉了什麼，為什麼

- **v0.3.0 拿掉「計數」分頁**：它要先選動作、填目標才能開始數，等於每天把同一件事重設一次。
  今天要做什麼本來就列在首頁上。
- **v0.4.0 拿掉「課表」**：一整套「排好一張表、照著一項一項跑、中間倒數休息、練完看摘要」的東西。
  它是最早的需求，但使用者自己的訓練表第三天就空了——**真正撐得下去的是每天同一份清單**，
  不是每次都要先規劃的課表。跟著走的還有組間休息設定、倒數提示音、訓練時螢幕常亮
  （那個旗標本來就只掛在執行畫面上）。

  **舊紀錄不動**：課表練出來的那些 `Session` 還在「紀錄」分頁裡，連當時的課表名字一起留著。
  裝置上的 `routines.json` 也不刪——功能拿掉不是把人家的資料刪掉的理由。
  v0.3.0 以前的備份檔照樣匯得進來，裡面的 `routines` 陣列會被忽略。

## 功能

- **計數**：首頁清單上每一列都是計數器。**點一下 ＋1**（帶一次鍵盤那種觸覺回饋），
  **長按連續加**（0.5 秒後開始，約每秒九下）——一次做二十下才想到要記的時候，
  一下一下點二十次太蠢。進度不另外畫進度條，而是**整列自己填滿**：列本身就是進度，
  一頁十列的話十條進度條會比十列文字還吵。
  **數字也可以直接改**（左滑 → 編輯）：忘記按、按太多下、在別的地方做完才想到要記，
  這些是靠點一下慢慢加回去補不完的。目標可以留空，那就是做幾下算幾下。
- **結算**：右上角那顆把今天寫成一筆紀錄。**沒按也不會掉**——跨到隔天時有做卻沒結算的，
  會在 `FitRepository.ensureToday()` 自動收進紀錄，所以這顆的意思是「現在就記下來」，
  不是「不按就不算」。同一天結算幾次都是更新同一筆（紀錄 id 由日期決定）。
- **連續天數與格子圖**：首頁最上面那塊。火的大小與顏色隨連續天數變，**但不會一直燒**——
  天數變動的那一刻彈一下而已（理由見下面「為什麼火不會一直動」）。
  底下是 GitHub 貢獻圖那種格子，一天一格、做越多顏色越深。
  **格子底下不寫「一天一格，做越多顏色越深」這種說明**：看圖就知道的事寫出來只是多一行字。
- **動作庫**：依部位分組、可收合，展開狀態記在本機。每個動作標**要用到的工具**
  （徒手／啞鈴／椅凳，可自己加），上面一排晶片可以依工具篩選——
  回答的是「我現在手邊有什麼就能做什麼」。列尾 ⋯ →「加到今天」會把它帶進今天的清單。
- **紀錄**：一天一筆，點進去看那天每一項做到幾下。沒做滿的用紅字標出來。
- **備份**：整包匯出／匯入 JSON，依 id 合併，重複匯入不會長出重複資料。
  預設清單整份換掉（它是有順序的樣板，合併會把刪掉的帶回來）；今天那份只在日期對得上時才收。

資料全部存在 App 私有目錄，沒有後端、沒有帳號、不連網。

## 內建的動作與清單

首次啟動會載入 24 個動作，以及一份每天的預設清單（伏地挺身／深蹲／核心，各 100 下），
裝好就能直接開始，不必先花時間建資料。

其中 23 個動作來自使用者原本的啞鈴訓練表，第 24 個是 `伏地挺身`。**重量一律留空**——
原始表格沒有這一欄，值該由使用者自己填。部位與工具的分類是依動作名稱推的，可以改。
預設清單那三項是使用者自己畫的（`FIT.DRAWIO`）。

內建動作之後才長出來的欄位（例如工具這一欄）會由 `FitRepository.migrateSeed` 一次性補齊，
只補使用者沒填過的，不覆蓋任何已有的值。

種子資料在 [`assets/seed_exercises.json`](app/src/main/assets/seed_exercises.json) 與
[`assets/seed_defaults.json`](app/src/main/assets/seed_defaults.json)。
使用者自己把動作或清單刪光就維持空的，不會再回填。

## 字體與顏色

兩條規則來自家族的視覺研究，都是裝置實測過的：

- **中文字重封頂 Medium(500)**。Android 14 以前的 zh-Hant 字體只宣告 weight 400，
  SemiBold 與 Bold 會觸發合成假粗，看起來是糊的。層級改用字級與顏色深淺做。
  字距 `0.sp`、行高 1.5×、`includeFontPadding = false`（不關中文會在行框裡偏下）。
  全部集中在 [`ui/theme/Type.kt`](app/src/main/java/com/routina/fit/ui/theme/Type.kt)。
- **砍顏色面積，不砍顏色數**。飽和填色一頁只留一個，其餘用容器色；
  清單列的進度是用容器色填滿，不是鋪飽和色。

整套色階是從家族種子色 `#4B5699` **算出來的**，不是手挑幾個值：在 Oklch 裡固定色相與彩度、
只變明度（選 Oklch 不選 CIELAB，因為藍色系在 Lab 提亮會往紫偏，而家族色正好是靛藍），
見 [`ui/theme/Palette.kt`](app/src/main/java/com/routina/fit/ui/theme/Palette.kt)。
`ColorScheme` 的每一個角色都給值——只要漏掉一個，Material 就會拿內建的**紫色**基線來補，
分頁列與晶片就會冒出與家族無關的紫。

帶意思的顏色只有三個，各自只講一件事：**進度**＝主色靛藍（列填滿的那一塊）、
**沒做滿**＝錯誤紅、**訓練量**＝琥珀（格子圖與那團火）。
格子圖不用 GitHub 的綠：綠在這套色階裡是留給「休息」的（課表拿掉後畫面上已經沒有綠，
但色階還在，不要讓同一個顏色之後又兼差）。琥珀離靛藍與紅都夠遠，而且差異落在明度與藍黃軸上，
紅綠色盲照樣分得出來。琥珀的梯子**最深停在 L\*52 不到 40**——琥珀到了 40 就是土色。
「那天沒練」那一格用中性灰而不是最淡的琥珀——有練和沒練是兩種東西，不是同一條梯子的最底層。

## 為什麼火不會一直動

那團火是**靜態向量**，只有大小與顏色隨連續天數變，天數變動時用一次 spring 彈一下。
不做持續燃燒是查過才決定的：

- **GIF 出局**。平台的 `AnimatedImageDrawable` 要 API 28，這個 App 的 minSdk 是 26；
  補上 Coil 的 `coil-gif` 會連帶拉進 core／okio／appcompat-resources／exifinterface 約 1 MB，
  而且 GIF 完全不理會系統的「移除動畫」設定。Lottie 更糟，它的 POM 會把 1.1 MB 的 appcompat
  拉進一個純 Compose 專案。AGSL 要 API 33。
- **一直動本身就是問題**。`InfiniteTransition` 每一個 vsync 都會喚起一次 frame callback，
  而首頁正是那個要被連按幾十下的畫面。NN/g 的結論很直白：重複遇到的動畫是內容的路障。
  實際產品也站這一邊——Duolingo 的常駐 streak 就是圖示加數字，火焰動畫只留給里程碑。
- **用 `animateFloatAsState` 順便免費拿到無障礙**。Compose 的動畫會從 `MotionDurationScale`
  讀到系統的動畫縮放，使用者開「移除動畫」時直接跳到結束值，火仍然是正確的大小。
  手刻 `InfiniteTransition` 會繞過這件事。

縮放讀值走 `Modifier.graphicsLayer { }` 的 lambda 版，只跑 draw 階段，不會每一格都重組。

## 為什麼沒有通知權限

這個 App 不會主動找你：沒有提醒、沒有背景服務、沒有通知權限。做到目標時會響一聲加震動，
但那是你正按著螢幕的時候。

## 家族

Fit 會出現在 [Routina](https://github.com/ImitatedSky/routina)（Hub）的家族目錄裡。
掛進家族只靠 manifest 的四個 meta-data，是字串層級的約定、不是程式碼依賴，
所以這個 repo 不引用 Hub 的任何 library。

對外開放的能力（讓 Routina Flow 可以定時打開今天的清單）還沒做。

## 建置

需要 JDK 17 與 Android SDK（`local.properties` 的 `sdk.dir`）。

```sh
./gradlew :app:assembleDebug
```

Release 在有完整簽章資訊時（根目錄 `keystore.properties` 或 CI 的 `KEYSTORE_*` 環境變數）
用正式簽章，否則沿用 debug 簽章。家族全體共用同一把 keystore，成員才能就地更新。

## 發版

`vX.Y.Z` 標籤會產出一個永久保留的 Release，附 `routina-fit-vX.Y.Z.apk`。
CI 會先擋下標籤與 `versionName` 不一致的發版。
